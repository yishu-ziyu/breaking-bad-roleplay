# 验证报告

## 核心假设

| # | 假设 | 验证方法 | 状态 |
|---|------|----------|------|
| 1 | 用户愿意跟版权角色对话 | 已有可运行原型 + 知乎/社区讨论佐证 | 未验证（需要真实用户测试） |
| 2 | Story 导演模式是差异化卖点 | 竞品对比 + 用户反馈 | 未验证 |
| 3 | 中文用户有未被满足的需求 | Character.ai 无中文优化、SillyTavern 门槛高 | 部分验证（证据充分，缺定量） |
| 4 | 免费 LLM 能支撑 MVP | Agnes AI 已跑通 + 多引擎 fallback | 已验证 |
| 5 | Vercel + Supabase 技术栈够用 | 已部署上线 + Chat/Story 可用 | 已验证 |

## 挑刺评审

1. **定位太宽**："AI 驱动的影视角色扮演"范围太大。建议先钉死 Breaking Bad，跑通再扩。
2. **Story 模式的 30 秒生成时间太长** — 用户耐心阈值约 5-10 秒。需要做渐进式生成（先出大纲，再逐 beat）。
3. **Non-goals 里"不做用户生成角色"可能太早限制** — 社区 UGC 是 Character.ai 的核心护城河。建议设为"Phase 3+"而非永久不做。
4. **没有变现路径** — 长期产品需要考虑。LLM API 成本随用户量增长，免费模式可持续性存疑。建议 Phase 1 末尾加入调研。
5. **角色记忆的方案太轻** — 当前只是把历史塞进 system prompt，token 消耗随对话增长线性上升。需要实现"摘要 + 关键事实"的滑动窗口。

## 最小验证

**核心假设验证**：用户是否愿意花 5 分钟跟 Breaking Bad 角色对话？

- 步骤 1：把当前产品 URL 发给 5-10 个目标用户（Breaking Bad 粉丝 / AI roleplay 爱好者）
- 步骤 2：记录：是否完成至少 3 轮对话 / 是否切换到 Story 模式 / 主动提了什么改进建议
- 判断标准：≥ 3/5 用户完成 3 轮以上对话 → 假设成立

## 范围一致性

跟定义阶段对比：
- 新增：无 — 设计方案在定义范围内
- 裁剪：无 — 设计方案覆盖了定义中的所有 P0/P1/P2 旅程
- 变更：数据模型比定义阶段更细化（加了 metadata_json 字段）— 合理细化，不改变范围
