## 语言处理（i18n）

### 原则：模型输出语言跟随用户界面语言，不跟随 prompt 的书写语言

产品支持中英双语。核心约束是：**叙事输出（对白、内心独白、动作、场景描述）的语言由用户选择的界面语言决定，而不是由 prompt 的书写语言决定**。

### 细节处理：中文母语者守则只作用于中文分支

为了消除"译制腔"（比如"一想到沃尔特那张嘴……我心里这块秩序的玻璃已经开始裂了"——这是英文骨架直译 + 抽象名词硬拼的产物），我们在中文分支里加了一段**中文母语者表达守则**：用中文思维而非从英文翻译、禁止英文直译骨架、禁止抽象+具体名词硬拼、短句直接带停顿、内心独白同样遵守，并锁死角色中文译名（麦克、杰西、汉克等，禁止音译乱写）。

**关键设计：这段守则只写进 `zh` 分支，英文分支保持纯英文。** 语言指令按用户的界面语言静态分叉：中文用户走 `zh` 分支（带母语者守则 + 固定译名），英文用户走 `en` 分支（纯英文指令，不含任何中文约束）。

因此，把"中文表达守则"加进 prompt **不会让英文用户感到不适**——这不是把 prompt 全局改成中文，而是条件分支。英文用户的输出语言、指令结构、角色语气都保持英文原样，只是不再被中文约束污染。

**对用户的影响**：
- 中文用户：获得母语者级别的自然表达，译名统一，无翻译腔。
- 英文用户：输出与之前完全一致，无任何感知变化。

**兜底与验证**：这属于 prompt 约束（治本）。若仍有漏网，由"译制腔检测 + 改写"守卫兜底，并用回归测试 + 人工 A/B 盲测 + 线上扩散检查三件套验证（详见 `.ship/tasks/20260804-agent-loop/pm/02-research-zh-dubbing-tone.md`）。

### 验证方法：双 Agent A/B 盲测（一个玩一个看）

问题：守则到底有没有让中文变自然？只看代码和单测不够，需要在真实对话里直接对比。

处理：用 `zh_guard` 开关做 A/B 对照组——对照组（`?zh_guard=0`）跳过守则、放大译制腔，实验组（默认）保留守则。派两个浏览器 agent 各玩一个版本，用真实操作进 Story、发同样的开场、抄下台词，再按三维度打分（母语自然度 / 英文语法痕迹 / 译制腔危害，各 1-10）。流程一句话：起本地前后端 → 派 browser agent 真实玩 Story → 对照组 / 实验组各跑 → 三维度打分 → 汇总分差。可复用的完整脚本见 `scripts/blind_ab_runner.md`。

对用户的影响：以后任何中文质量改动都能复用这套盲测，不用每次重写流程，结论有据可查。

**结论**：三角色 A/B 实测（Walter / Jesse / Skyler，同角色同开场两版对比）显示守则对中文质量有稳定正向影响。平均分差（对照 − 实验）：母语自然度 **+1.7**，英文语法痕迹 **−2.0**，译制腔危害 **−2.3**。即守则让中文更自然、英文直译痕迹更少、译制腔危害更小。实验组（跳过守则）中文仍可用，不会崩坏，但明显更书面、更舞台化、更接近字幕腔。分差明细见 `scripts/blind_ab_runner.md` 的分差汇总模板。

### 决策：译制腔改写守卫优先级下调

问题：`zh_guard` 开关已实现，改写守卫（检测命中 → LLM 重写）也已做出原型。但盲测显示守则本身已把中文拉到 8 分档，实验组漏网率不高（+1.7 分差，非灾难级）。

处理：下调改写守卫的投入优先级。理由——守卫是"把 8 分拉到 8.5 分"的边际优化，而守则注入是"把 6-7 分拉到 8 分"的主防线，两者成本不成比例。守卫每命中一次都要额外一次 LLM 调用（贵、需网络），而漏网率本就低，边际收益有限。保留守卫代码（作为探针与兜底），但不优先上线。

对用户的影响：不主动投放改写守卫，避免不必要的额外延迟与成本；中文质量由守则保证。若未来线上扩散检查显示漏网率上升，再激活守卫。
