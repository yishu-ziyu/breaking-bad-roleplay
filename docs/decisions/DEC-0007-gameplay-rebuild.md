# DEC-0007 · 玩法重构：从「事件日志」到「一场戏」

> 状态：PROPOSED（待用户拍板后进入实施）
> 日期：2026-08-27
> 触发：QA + 用户判断——主舞台是事件日志流，不是戏剧。天花板优先，不担心工程量。
> 关联：DEC-0003（McKee 节拍引擎）、DEC-0005（propose-validate-commit）、GAME_UX_PLAYBOOK

## 0. 判决：为什么现在的玩法立不住

主舞台把 Director 的事件（`scene_change`/`agent_speak`/`agent_think`/`agent_act`/
`world_state_delta`）按顺序渲染成日志条目。这在架构上方便，在体验上是三个死刑：

1. **没有"此刻"**。日志是平的：第一行和第八行同样大小、同样灰。玩家没有
   "现在是这句话最重要"的视觉锚点。戏剧 = 某一秒比另一秒重要。
2. **没有身体**。角色是一行 `character_id` 文字。Walter 说话和 Jesse 说话长得一模一样。
   你感觉不到"谁在房间里"。
3. **选择没有分量**。三个 chips 是通用的（施压/动手/看清），不管剧情正在发生什么。
   按 inkle 的说法：玩家在问"我的选择真的重要吗？"——现在的 UI 每天都在回答"不重要"。

## 1. 三个老师，各取一样东西

### 1.1 Disco Elysium —— 「失败也是戏」+「房间里有声音」

- **取**：行动可以失败，失败的演出和成功一样有味道（白检定可重试、红检定永久，
  失败解锁独特剧情）。现在的游戏里玩家输入什么都能"成功"，于是输入没有张力。
- **取**：内心声音。DE 的技能会插嘴（"恐惧会说服你先走为敬"）。
  我们的角色是绝命毒师宇宙——Walter 的 Heisenberg 声音、Jesse 的愧疚声音，是现成的
  戏剧资产，现在完全没用上。
- **不取**：2d6 数值检定（我们不是 RPG，不引入数值板）。

### 1.2 80 Days（inkle）—— 「文字是视觉媒介」+「选择服务节奏」

- **取**：舞台呈现是一段**排印过的段落**，不是聊天气泡。每拍 = 一个镜头：
  场景一句话（斜体定场）→ 动作白描 → 台词带说话者名牌 → 收在悬而未决的那一句。
- **取**：高频轻选择 + 低频重选择交替。80 Days 的选择大多是"走哪条路"级别的节奏器，
  大决定偶尔出现才有千钧重。对应到我们：每拍 1 个轻选择（往哪推），每 2-3 拍
  1 个重选择（方向性、不可逆）。
- **不取**：百万字手写分支（我们靠 LLM 生成）。

### 1.3 现有资产盘点（不推倒的底座）

| 资产 | 状态 | 重构中的角色 |
|---|---|---|
| McKee 节拍引擎（DEC-0003/0005） | ✅ 稳定生产 outline+beat | 保留，是节奏的来源 |
| SSE 流式事件 | ✅ | 保留传输层，**渲染层重写** |
| world_state_delta | ✅ | 升级为"后果可见"系统的数据源 |
| world clock（第 N 天·时段·天气） | ✅ 已有数据 | 提升为舞台常驻定场 |
| 角色 TTS / GIF | ✅ | 台词镜头里作为可选呈现 |
| 记忆/档案/局面图 | ✅ | 不动 |
| 决策 chips | ⚠️ 通用三件套 | 重写为「拍级导演指令」 |

## 2. 新核心循环（一句话版）

> **每一拍是一场镜头：定场 → 戏 → 收束于悬念；你以"导演指令"介入，镜头重拍；
> 后果沉淀为可见的世界状态；Heisenberg 在你耳边说话。**

```
定场（场景+时钟，2 秒读完）
  └─ 戏（台词为主体的排印段落，流式打字机）
       └─ 收束（最后一行永远悬着：一个未回应的问题/一个进门的人/一句没说完的话）
            └─ 导演指令（你的输入点，见 §4）
                 └─ 后果闪现（一句话，淡入淡出）
                      └─ 下一镜头
```

## 3. 舞台层（视觉/呈现）设计

### 3.1 镜头（Shot）= 舞台的一屏

- **场景定场**：顶部细字一行情境（`沙漠房车 · 第 1 天 傍晚 · 晴`已有 world clock 数据）。
  场景切换时整屏字幕卡 1.2s（黑底大字场景名），然后淡入新镜头。
- **台词为主体**：说话者的台词是**唯一的大字**（文楷，20-26px），居中偏左，打字机流入。
  说话者名牌 + 剪影在台词左侧固定（解决"Walter 照片配 Jesse 台词"——名牌/剪影绑定
  `character_id`，不信任消息顺序）。
- **动作/内心**：动作白描用无名牌的窄栏散文；内心声音（think）用**斜体+括号**，
  而且现在就升级为"声音"：如果说话者是 Walter 且契约标记了 Heisenberg 浮现，
  内心行用 Heisenberg 的语气渲染（LLM 侧生成，前端只管样式区分）。
- **后果闪现**：`world_state_delta` 不再是常驻面板。变化时舞台右下浮现一句话
  （「安全 → 隐隐不安」翻译成人话：「有什么东西开始不对劲了」），4 秒淡出。
  完整账本收进「局面」抽屉（已有）。
- **删除**：分镜页码（4/6）、事件类型 chip（说/做/观察的 rail 标签）、GIF 默认开
  （GIF 降级为可选装饰，默认关）。

### 3.2 打破日志感的排版规则

- 一屏最多一个"最重要"：当前播放行 100% 不透明度，已读行降到 40% 且缩小一号。
- 空间换时间：拍与拍之间用整屏呼吸（1 行高的空白+分隔点），不再用边框盒子。
- 文字宽度 38em 硬上限（可读性），屏幕其余部分留给夜色背景。

## 4. 选择层（导演指令）设计

### 4.1 三档输入，取代"通用三 chips"

| 档 | 界面 | 例子 | 频率 |
|---|---|---|---|
| **轻推** | 2 个剧情派生短 chips（本拍 LLM 顺手生成） | 「顺着杰西的话逼问托德」「先不接话，看他手势」 | 每拍 |
| **定调** | 1 个方向选择（何时出现由 Director 契约决定） | 「这一夜往暴力走」「往欺骗走」 | 每 2-3 拍 |
| **自由** | 打字框（现状保留） | 任何事 | 永远可用 |

- 轻推 chips 由 **beat 生成时顺带产出**（LLM 在 beat JSON 里多吐 2 个
  `player_options`），不再是前端写死的通用三件套——这是"选择长在剧情上"的关键。
- 定调选择的**不可逆性**要演出来：选中后舞台短暂压黑 0.6s，之后本拍的演出色调
  微移（暴力偏红/欺骗偏蓝绿）——用现有 CSS 变量做，成本低。
- **失败与代价（DE 课）**：自由输入和轻推都可以被 Director 判定"不顺"
  （角色拒绝、警察 nearer、杰西跑掉半条街）。失败不是 error，是一段正常演出。
  前端只加一个「不顺」的舞台提示样式（文字轻微下沉+冷色一拍）。

### 4.2 内心声音（Heisenberg 侧轨）

- Walter 视角下，每拍至多一次，舞台左侧浮现一行小斜体（Heisenberg 声音）：
  「你在-resolution 前软过一次。别再软。」
- 数据来源：beat 契约已有 `mckee_role`/`beat_contract`；Director 在生成时多吐一个
  `inner_voice` 字段（Walter 专属，其他角色先留空）。前端纯样式。

## 5. 状态层（可见的世界）

- **关系条**：你与在场角色的关系值变化（`trust/risk` 已在 dossier 数据里），
  在定场行以微表情词显示：「杰西 · 动摇」。
- **夜之余量**：「这一夜大约还有 N 处关口」已有，提升到定场行右侧，作为紧张度计。
- 其余（局面图/档案/剧情图谱）不动，仍是主动打开的抽屉。

## 6. 实施计划（三步，每步可独立验收）

| 步 | 内容 | 触及 | 验收 |
|---|---|---|---|
| **S1 镜头舞台** | 前端渲染层重写：Shot 组件（定场/台词主体/已读淡化/后果闪现/场景字幕卡）；删页码与 rail chips | 纯前端，新组件 + App 挂载点 | 现有事件流喂进新舞台，视觉验收 |
| **S2 派生选择** | Director beat JSON 增加 `player_options`（2 轻推+可选 1 定调）+ `inner_voice`；前端 chips 改吃数据，fallback 到通用三件套 | 后端 prompt+解析、前端 chips | 新会话里 chips 长在剧情上 |
| **S3 代价与声音** | 失败路径演出样式；定调选择的压黑+色调微移；Heisenberg 侧轨渲染 | 前端样式为主 | 玩一场能感知"介入有分量" |

S1 不动后端，一天内可出可玩版本。S2/S3 依赖 beat 契约扩展，各约一天。
总计约 3 个工作日到全量。

## 7. 明确不做

- 不引入数值系统（骰子/属性板）——张力来自处境，不来自数字
- 不做分支树可视化编辑器——LLM 直出
- 不动单聊/群聊 surface（它们是低杠杆的旁路模式）
- 不追求 80 Days 级手写文本质量——接受 LLM 文本的上限，用排印和节奏弥补
