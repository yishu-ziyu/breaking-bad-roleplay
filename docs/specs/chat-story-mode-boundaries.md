# 三种模式的产品边界与验收

用户本轮确认：Direct 是一对一 AI 角色聊天；Crew 是多角色 AI 聊天；Story 才是行动、结算、后果驱动的叙事游戏。三个入口保持并列，不强制串成一条任务链。

## 本轮范围

- Story 玩家身份不得改写独立聊天对象。返回 Story 时仍使用该局实际玩家身份。
- Direct / Crew 各自保存记录、关系锚点和草稿；Direct 的私聊记忆不得自动传入 Crew。
- 云端查询、回填和写入使用相同的模式隔离键，沿用 user_id RLS 和客户端加密。
- 老版本未标注模式的记录不猜测归属、不删除；单独只读回看，不自动进入新对话上下文。
- 后端独立聊天入口只接收聊天上下文，不加载 Story 存档或结算游戏状态。复用角色能力不等于共享进度。
- 不修改 Story 网络恢复算法、数据库账本、首页视觉或 Crew 抢话算法；这些是其他任务。只在 useStoryStream 的自动恢复入口增加模式激活开关，防止打开聊天时后台续跑旧 Story。

## Given / When / Then

1. Given 单聊里有私密对话，When 切换群聊并发送消息，Then 群聊正文与模型请求都没有私聊记录或私聊记忆；切回单聊仍有原记录。
2. Given 正在和 Saul 单聊且本地有玩家为 Jesse 的 Story 存档，When 存档恢复，Then 单聊仍是 Saul；切到 Story 才显示 Jesse。
3. Given 旧版未分类聊天，When 打开新聊天，Then 旧记录只在明确标注的历史区回看，不成为本轮 history/durableMemory，也不被回填成新模式数据。
4. Given 独立聊天请求夹带 Story session/world 字段，When 进入角色运行入口，Then 只保留允许的聊天字段，不读取剧情数据库。
5. Given 切换模式时旧请求仍在返回，Then 回复只落入原线程，不覆盖新模式的草稿/错误状态。

## 交付边界

存储实现：沿用现有 TEXT `character_id` 列，写入版本化聊天线程键 `chat-v2:<mode>:<NPC id>`；真正的角色 id 只用于模型请求、发言人和头像。旧裸角色键的数据只读，不做推断式搬迁。Direct 记忆使用同一线程键；Crew 不读取 Direct durable memory。旧客户端没有模式边界，不应与新版交替使用来继续同一段聊天。

浏览器验证使用项目已安装的 Playwright（本会话无 Browser 插件），在独立测试端口运行，模型与 Supabase 为可编排假服务；不以此声称真实模型文学质量或生产云同步已经验收。

只修改本地工作树，运行前后端测试、模式隔离 E2E、build/lint；不 commit、push、部署或操作生产库。现存网络修复不作为本轮完成项。
